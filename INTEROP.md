No implementation code, decompiled code, binary resources, or interface artwork is included here. These findings define compatibility research targets; they do not establish behavioral parity.

## Documented automation surface

The official [API overview](https://www.think-cell.com/en/resources/manual/api), [Excel automation manual](https://www.think-cell.com/en/resources/manual/exceldataautomation), and [style API documentation](https://www.think-cell.com/en/resources/manual/style-files) corroborate the following names as supported automation functions. DISPIDs and GUIDs below come from the inspected artifact. Signatures use Automation value types, not C pointer syntax. `IDispatch` denotes VT_DISPATCH; `out retval T` denotes a VT_PTR to T with FOUT and FRETVAL. Native calls return HRESULT. `VARIANT_BOOL` is the Automation Boolean type.

Two additional types define connect/disconnect enum values. The 905 total includes macro interfaces and events, not 905 distinct user features. Most large-interface members are UI callbacks or host integration declarations; their presence establishes neither documented support nor full behavior.

`IPpMacroInterface` also declares activation, gallery/table insertion, and application-specific helper methods. The seven methods with DISPIDs 9911808–9911814 have names ending in `Step2` or `Step3`; these are treated as internal transport interfaces. In particular, `UpdateBatchStep3` takes parallel name/target/storage arrays and a count. No compatibility promise should rely on these internal-looking names yet.

Static tracing provides stronger evidence for the batch path: the concrete update object's vtable matches the validated three-method interface; both AddRange methods converge on one implementation body; Send constructs Automation arrays and ultimately calls `IDispatch.Invoke` with DISPID 9911810, which matches `UpdateBatchStep3`. It passes arrays of BSTR, IDispatch, and IUnknown plus an integer count. An empty-state branch requests an error requiring at least one range. This establishes an internal handoff, but does not establish atomicity, rollback, duplicate-name behavior, or the storage format.

## Native host architecture

Independent static PE, exception-table, Capstone, and MSVC RTTI analysis supports this path:

1. The exported `DllGetClassObject` reaches a class table containing the installed add-in CLSID `{D52B1FA2-1EF8-4035-9DA6-8AD0F40267A1}`. The table connects it to an ATL class factory and `thinkcell_addin` object creator.
2. The concrete add-in exposes separate lifecycle, ribbon, and custom task pane interfaces. `OnConnection` validates required interface pointers, obtains the add-in interface, and constructs a host delegate. Host selection queries distinct application interfaces and verifies the expected PowerPoint or Excel process name.
3. Top-level `GetIDsOfNames` and `Invoke` forward to the host delegate's dispatcher. The observed host dispatchers resolve names and invoke members through type information.
4. PowerPoint `GetCustomUI` checks `Microsoft.PowerPoint.Presentation`; Excel checks `Microsoft.Excel.Workbook`. Each selects host-specific ribbon material, then calls a shared builder. Excel has two template variants; the selection condition is not understood.
5. A PowerPoint persistence path references the hidden shape name `think-cell data - do not delete` plus tag keys `THINKCELLSHAPEDONOTDELETE` and `thinkcellActiveDocDoNotDelete`. This corroborates the separately inspected reference presentation's hidden OLE data object. It does not establish a complete serialization algorithm.

The exact addresses and decoded evidence observations remain in the private research file `native-findings.json`. Reconstruction should use original host adapters, independently designed ribbon controls, and an explicit persistence model. Matching declarations is only one layer; editing behavior, layouts, update edge cases, and round-trip fidelity still need separate tests.

## Limitations

No proprietary target execution occurred. These native interface findings have not been compared with think-cell runtime behavior. Separate rendering checks use PowerPoint to display cached chart content from a reference presentation; see VALIDATION.md. After an earlier startup timeout, Ghidra completed analysis in approximately 33 minutes under a larger process-local startup budget. The four dossiers and their evidence were saved, then the session closed successfully. The saved snapshot contains those cached results; the temporary whole-program Ghidra database was deleted on close. Ghidra's inferred types and indirect-call resolution remain incomplete. Static callback signatures and class structure alone cannot justify a claim that an open-source implementation is identical.
